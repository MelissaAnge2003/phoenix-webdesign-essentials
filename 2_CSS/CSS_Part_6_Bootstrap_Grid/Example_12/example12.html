Theory

A grid system can be compared to a simple construction kit. It's best to follow the included instructions closely and add your own touches to a limited extent, but you must use the kit's components correctly, otherwise the final result will be difficult to maintain or even unusable.

Tips

1. The labor costs are often too high to code every website from scratch. In practice, it's better to work with pre-built components so you can build websites faster. Grid systems provide a useful foundation for quickly creating a site that requires a columnar layout. Thanks to such a grid system, you can quickly achieve the desired result by adding the correct class names, without having to write your own code in a CSS file for positioning.

2. When using a grid system, write AS LITTLE CSS as possible yourself and look for class names that are already present in the grid system and that you need to add to the tags in HTML to get the end result you want.

3. NEVER change anything in the CSS file associated with the grid system, or you'll have to re-implement all the changes during the next grid system update. This means you're writing your own CSS in a DIFFERENT CSS file that's loaded AFTER the grid system.

A. With responsive web design, you start with the content, which needs to be displayed correctly on all devices. "Content first!"

B. With responsive web design, it's best to start with a narrow-screen design before considering a wide-screen design. First, ensure mobile users can do/find/control everything on the site, and only then move on to a design for users who can view more elements simultaneously. This is more effective than starting with a large-screen design and then omitting elements for smaller screens. So, "Mobile first!"
